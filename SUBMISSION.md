# Superteam submission packet — no-tx submission

## One-line pitch
Cookie Alpha Radar turns Cookie Chain market data into explainable alpha + risk signals, compares Cookiebox and Candy Shop execution, and gives Nightly users a non-custodial path from discovery to transaction-ready actions on Cookie Chain.

## What makes it different
- Not a passive dashboard: discovery can progress into a transaction-ready swap or an on-chain watch-proof flow.
- Dual-router execution: Cookiebox and Candy Shop are compared by output before the user signs.
- Explainable Alpha + separate risk model: momentum is never treated as safety.
- Fail-honest data handling: missing upstream values stay missing.
- Nightly-first flow: explicit Cookie Chain network switch helper.
- Wallet intelligence: native COOK balance, CookieScan DAS holdings and recent Cookie Chain signatures after Nightly connects.
- Outage resilience: a clearly labeled synthetic fixture is opt-in only and cannot execute transactions.
- Payment-grade execution checks: server-side fresh re-quote, client route identity/output/fee-payer validation, signed-tx simulation, then broadcast path.
- Activity journal: locally records user-visible success/failure states and can export JSON/CSV.

## Submission disclosure
The application implements real Cookie Chain transaction execution paths, confirmation handling, and failure feedback. This submission does **not** claim that the author personally broadcast a mainnet transaction for the demo. No transaction signature is presented as evidence unless one is actually generated by a user of the app.

## Demo sequence — no broadcast required
1. Open Alpha Board and show CookieScan-backed token rows.
2. Explain one score: liquidity + flow + turnover − volatility.
3. Open a mint on CookieScan.
4. Connect Nightly and display the connected address.
5. Use `Set Nightly → Cookie` and show the Cookie Chain RPC/network configuration.
6. Show wallet intelligence: COOK balance, DAS assets and recent Cookie Chain signatures when available.
7. Open Smart Swap and compare Cookiebox vs Candy Shop routes.
8. Show the fresh server-side re-quote, route identity, output/slippage checks and fee-payer validation before any signature is requested.
9. Show the transaction status/error UI and Activity Journal without broadcasting a transaction.
10. Show the current Hyperlane bridge guide for users who need COOK.

## Smart Router
The app compares two Cookie Chain aggregation paths used by the ecosystem:
- Cookiebox Aggregator (`agg.cookiebox.app`)
- Candy Shop / CookieScan Swap API (`swap.cookiescan.io/api`)

Execution path implemented in the app: quote → server re-quote → validate fresh output + fee payer → wallet review/sign → Cookie RPC simulation → broadcast → confirmation.
